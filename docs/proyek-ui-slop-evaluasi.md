# Evaluasi Potensi UI Slop Proyek

**Tanggal:** 18 Oktober 2026  
**Metode:** inspeksi source code dan pengujian browser lokal menggunakan akun Waka Kesiswaan.  
**Kesimpulan:** UI memiliki fondasi yang cukup konsisten dan beberapa pola aksesibilitas yang baik, tetapi berulangnya pola kartu, kicker, serta tipografi kecil membuat beberapa layar terasa seperti template dashboard generik. Pengujian ulang juga mengonfirmasi dua masalah yang dapat diamati langsung: dialog navigasi mobile tidak menahan fokus keyboard, dan metrik laporan tetap menampilkan nol sementara status laporan masih memuat.

## Cakupan dan batasan

Pemeriksaan source meliputi fondasi global, login, portal utama, navigasi mobile, jurnal, input perilaku, laporan, rekap kehadiran, profil, direktori siswa, admin, serta komponen dialog. Login lokal berhasil dengan akun yang diberikan; profil terautentikasi menunjukkan peran **Waka Kesiswaan** dan **Guru Mapel**, dengan enam menu portal. Rute yang diperiksa: Portal, Input Perilaku, Laporan, Rekap Kehadiran, Direktori Siswa, Profil, dan Jurnal.

Tampilan mobile diperiksa pada viewport 391 × 844 CSS px; rute yang disampel tidak menunjukkan overflow horizontal (lebar dokumen 376 px karena area scrollbar browser). Portal utama juga diperiksa pada desktop 1441 × 901 CSS px tanpa overflow horizontal. Pengujian keyboard pada drawer mobile dilakukan langsung. Tidak ada formulir yang disimpan atau data yang diubah. Admin tidak diuji karena tidak tersedia dalam menu peran akun ini. Pada pemuatan awal server sempat mencatat kegagalan resolusi `sonner`; sesudah server siap, login dan rute portal berhasil dibuka. Tidak dilakukan pengukuran kontras otomatis, pengujian zoom 200%, screen reader, atau perangkat nyata.

## Hal yang sudah baik

- Form login memakai label yang terhubung ke input, `autocomplete`, validasi dasar browser, target kontrol yang cukup besar, serta pesan kegagalan dengan `role="alert"` ([app/login/page.tsx](../app/login/page.tsx#L78)).
- Navigasi mobile menyatakan label navigasi, menandai halaman aktif dengan `aria-current`, dan menyediakan target sentuh minimum 44 px pada navigasi bawah ([app/portal/components/mobile-nav.tsx](../app/portal/components/mobile-nav.tsx#L95)).
- Portal dan laporan memanfaatkan token warna semantik untuk sebagian besar latar, teks, batas, dan fokus. Halaman laporan juga memiliki indikator pemuatan dan empty state eksplisit.
- Pada ukuran mobile dan desktop yang diuji, tidak ditemukan horizontal overflow pada halaman yang disampel. Rute yang bisa dibuka menampilkan empty state tanpa error aplikasi yang tampak.
- Halaman beranda langsung mengarahkan pengguna ke login, bukan menampilkan landing page dekoratif yang tidak terkait dengan alur aplikasi.

## Prioritas tindak lanjut

1. Perbaiki pengelolaan fokus drawer navigasi mobile dan hilangkan landmark `<main>` yang bersarang.
2. Ganti nilai nol sementara pada kartu laporan dengan state loading yang jelas; investigasi terpisah dapat dilakukan bila pemuatan data laporan terus berlangsung lama.
3. Uji ulang dengan keyboard dan screen reader, zoom 200%, serta pengukuran kontras; lanjutkan pengujian Admin menggunakan akun yang memang berhak.
4. Tinjau penggunaan pola kartu dan teks kecil sebagai penyempurnaan visual; jangan mengubah gaya hanya untuk menambah dekorasi atau kebaruan.
